16Operations & Deployment

16.1 Installation

Dependencies are layered across three requirement files so that environments not requiring GPU acceleration are not obliged to download approximately 1.3 GB of CUDA runtime wheels.

FileAddsIntended use
requirements.txtBaseComplete CPU-only operation. Sufficient to run the system.
requirements-gpu.txt+ cuBLAS, cuDNNGPU-accelerated recognition on the reference configuration.
requirements-dev.txt+ pytest, ruffDevelopment and continuous integration. Deliberately excludes the GPU wheels.
 
# 1. Create and populate the environment
python -m venv venv
venv\Scripts\python.exe -m pip install -r requirements-gpu.txt

# 2. Install the model runtime and pull the model
ollama pull llama3.2:3b

# 3. Place the Piper voice model at models/piper/
#    (en_US-lessac-medium.onnx and its .onnx.json)

# 4. Verify every dependency independently
venv\Scripts\python.exe verify_setup.py

verify_setup.py reports each of the four dependencies separately, so a single failure does not obscure the status of the others. All four report healthy on the reference configuration.

16.2 Configuration

No configuration is required for default operation. To override, copy .env.example to .env and edit the relevant entries; every variable is documented in Table 10.3. Values are validated at start-up, and an unparseable value raises a diagnostic naming the variable rather than failing later in an unrelated component.

16.5 Troubleshooting Runbook

Table 16.1 — Observed failures and remedies
SymptomCauseRemedy
Library cublas64_12.dll is not found at first inferenceCUDA runtime libraries not on the process search path; construction succeeded but inference cannot (§8.4.2).Install requirements-gpu.txt. src/cuda_dlls.py handles path injection automatically thereafter. The system falls back to CPU regardless.
Activation script blocked by execution policyWindows PowerShell restricts script execution by default.Invoke the interpreter directly — venv\Scripts\python.exe <script> — which requires no activation.
Recognition device shows no value at start-upExpected: the recogniser loads lazily on first use.None. The indicator populates after the first transcription.
First response markedly slower than subsequent onesOne-time model residency load in the model runtime.None. Communicated to the user by design (NFR-P.5).
Diagnostic reporting the model server unreachableOllama not running, or a different address configured.Start the Ollama service; confirm OLLAMA_URL.
Frequent requests to repeatConfidence threshold miscalibrated for this speaker or microphone (§15.3.2).Inspect confidence_log.csv; lower CONFIDENCE_THRESHOLD (more negative) if scores cluster just below it.
Microphone permission not requestedPage not served from a secure context.Access via localhost, which browsers treat as secure. Any other host requires HTTPS.
Port already in useA previous instance is still running.Terminate it, or set CHAT_WEB_PORT / RECORD_WEB_PORT.
Transient MemoryError in preprocessingJust-in-time compilation under memory pressure (§8.3.3).None required — the stage degrades to unmodified audio and logs the event. Close other memory-intensive applications if persistent.

16.6 Offline Verification

The system’s central claim can be verified directly by the operator: disable all network interfaces and repeat a full conversational turn. Behaviour is unchanged, because every dependency resolves to a local file or the loopback interface. This is the recommended demonstration of NFR-S.1.

17Known Limitations

Limitations are recorded with their cause and, where applicable, the section that discusses them in depth. Items marked by design are consequences of accepted scope rather than defects.

Table 17.1 — Known limitations at baseline
IDLimitationClassDetail
LIM-01Pitch and rate correction disabledEvidencedDemonstrated harmful for isolated command words (§12.4). Detection remains active. Re-enabling requires fresh measurement and defeats a regression test.
LIM-02Confidence threshold calibrated on one speakerFairnessMay distribute repeat requests unequally across speakers (§15.3.2). Configurable, with an audit trail supporting recalibration.
LIM-03Evaluation limited to 25 clips, one speaker, isolated wordsEvidenceBounds the strength of accuracy claims (§12.7).
LIM-04No authentication or transport encryptionBy designSingle-user localhost operation only (RSK-01, RSK-02).
LIM-05Confidence log grows without bound and retains transcribed speechOpenRetention obligation not discharged (RSK-03, §15.2). Remediation specified but not implemented.
LIM-06Conversation history is not persistedBy designBrowser memory only; lost on reload (§9.3). Also a privacy benefit.
LIM-07Synthesis begins only after generation completesOpenSentence-level streaming synthesis would reduce time-to-first-audio. Identified but not implemented.
LIM-08No barge-inBy designThe assistant cannot be interrupted mid-utterance by speech.
LIM-09No wake wordBy designExplicit activation is a deliberate privacy property (§15.2).
LIM-10Single language (English)By designRecognition is pinned to English; the voice model is US English.
LIM-11Automated tests do not exercise real GPU, model server, or synthesiserAcceptedDeliberate trade for CI portability; integration covered manually (§11.5).
LIM-12No screen-reader or assistive-technology testingOpenAccessibility gap stated rather than assumed satisfied (§15.5).
LIM-13No packaging, installer, or container imageBy designDistribution is by repository clone (§2.3.2).
LIM-14Single concurrent user; no request queueingBy designConsistent with ASM-01 and RSK-06.
LIM-15Licensing obligations unresolved for redistributionOpenGPL-3.0 synthesis engine and non-standard model weight terms (§15.8).

18Future Work

Candidate work is grouped by the objective it serves and ordered by the ratio of expected benefit to effort. Items are traceable to the limitation or risk that motivates them.

18.1 Near Term — closes an identified gap

RefItemRationale and expected effect
FW-01Rotation, retention limit, and redaction mode for the confidence logDischarges the retention obligation in §15.2 and closes LIM-05 and RSK-03. Small, self-contained change.
FW-02Sentence-level streaming synthesisBegin synthesising the first complete sentence while generation continues; materially reduces time-to-first-audio. Closes LIM-07.
FW-03Filename sanitisation on recorder uploadsRemoves RSK-04 independently of the trust-boundary argument.
FW-04Screen-reader and keyboard-navigation auditConverts LIM-12 from an unknown into a measured position.

18.2 Medium Term — strengthens the evidence base

RefItemRationale and expected effect
FW-05Multi-speaker evaluation corpusAddresses the most significant threat to validity (§12.7) and would quantify the fairness concern in §15.3.2 rather than leaving it as a reasoned inference.
FW-06Adaptive or per-speaker threshold calibrationDerive the threshold from an initial calibration sample rather than fixing it globally. Directly mitigates LIM-02.
FW-07Continuous-speech benchmarkThe ablation in §12.4 justifies disabling rate correction for isolated words only. A multi-word corpus would establish whether the technique has merit in the regime it was designed for.
FW-08Noise-robustness evaluationExtends validity beyond the quiet-environment assumption.
FW-09Latency instrumentation with percentile reportingReplaces the indicative single-run figures in §13.1 with distributions.

18.3 Longer Term — extends capability

RefItemRationale and expected effect
FW-10Barge-in supportAllow the speaker to interrupt playback, which is the largest remaining gap against natural conversational rhythm. Closes LIM-08.
FW-11Optional persistent conversation historyLocal storage with explicit user control and an erasure path. Must be weighed against the privacy benefit currently obtained from non-persistence (LIM-06).
FW-12Packaging as a distributable applicationRemoves the repository-clone prerequisite. Requires the licensing questions in §15.8 to be resolved first.
FW-13Multilingual recognition and synthesisRemoves LIM-10; contingent on suitable local voice models.
FW-14Authentication and TLSPrerequisite for any deployment beyond a single local user (LIM-04). Note that this trades away the architectural privacy property described in §15.1 and should be undertaken only with that trade explicit.

Appendix D — Glossary of Decisions

A consolidated index of the non-obvious decisions in this document, for reviewers seeking the reasoning rather than the specification.

DecisionSectionOne-line rationale
RMS rather than peak normalisation§8.3.1Peak level is driven by a single sample and does not represent sustained loudness.
Trial inference before trusting the GPU§8.4.1Construction succeeds on Windows even when inference cannot; the fault is otherwise latent until first use.
PATH injection rather than add_dll_directory§8.4.2The conventional API is silently ineffective for LoadLibrary-based resolution.
Two-pass decoding rather than a single wide beam§8.4.3Pays the cost of a wider search only for utterances that need it.
Logging accepted decisions as well as rejections§8.5.4A log of failures alone cannot establish a false-rejection rate.
System prompt constraining response form§8.6.1Structure that aids reading actively harms listening.
Retry only before first output§8.6.3Restarting after partial delivery would duplicate content already seen or heard.
Resolving the synthesiser from sys.executable§8.7Removes dependence on shell activation state.
Flat files rather than a database§9.3Evidence artefacts benefit from being directly inspectable at this scale.
Mocking all external services in tests§11.1Portability and determinism, at the acknowledged cost of integration coverage.
Disabling pitch and rate correction§12.4Measurement demonstrated a 48-point accuracy reduction.
Declining hosted deployment§15.1It would forfeit the architectural property that justifies the design.
