Functional & Technical Specification

Local Voice Chatbot

A modulation-robust, fully offline speech-to-speech assistant integrating on-device speech recognition, a local large language model, and neural text-to-speech.

This document specifies the functional and non-functional requirements, system architecture, detailed design, verification strategy, experimental evaluation, and ethical assessment of the Local Voice Chatbot system. The system executes a complete speech-to-speech conversational pipeline entirely on local hardware, with no external network dependency at any stage. It incorporates an explicit confidence-gating layer that prevents low-confidence transcriptions from reaching the language model, and a measured, benchmark-driven approach to validating robustness claims — including a documented negative experimental result and the corrective action taken in response to it.

1Executive Summary

The Local Voice Chatbot is a speech-to-speech conversational assistant that runs its entire processing chain — speech recognition, language modelling, and speech synthesis — on local hardware. No audio, transcript, or generated response is transmitted to any external service at any point. The system was developed to address a specific reliability problem in voice interfaces: speech recognition models degrade when input is delivered under atypical vocal modulation (whispered, shouted, unusually slow or fast), and they typically fail silently, emitting a confident but incorrect transcription that downstream components then act upon.

The system addresses this in two layers. First, an audio preprocessing stage normalises input before recognition. Second — and more consequentially — a confidence-gating layer inspects the recogniser's own token-level log-probability for every utterance and refuses to forward low-confidence transcriptions to the language model, instead re-attempting recognition with a wider beam search and, failing that, explicitly asking the speaker to repeat. Every such decision is written to a persistent audit log.

Principal Outcomes

  • A complete, working offline pipeline. Microphone capture with voice-activity detection, GPU-accelerated recognition via faster-whisper, response generation via a locally-served 3-billion-parameter language model, and neural speech synthesis via Piper — all verified operating end-to-end on a 4 GB consumer laptop GPU.
  • A confidence-aware safety layer that converts silent recognition failures into explicit, recoverable interactions, with a complete audit trail.
  • A documented negative experimental result. The pitch- and speed-correction components of the preprocessing layer were hypothesised to improve robustness. Benchmarking against a purpose-recorded 25-clip dataset demonstrated the opposite: they reduced accuracy from 96.0% to 48.0%. The cause was isolated through controlled ablation, the components were disabled, accuracy was restored to parity, and an automated regression test now prevents the defect from recurring. This result, and the decision taken in response to it, is reported in full in §12.
  • Production-oriented engineering practice: centralised and validated configuration, a 42-test automated suite with continuous integration, consistent structured error handling, retry semantics on inter-process calls, log rotation, and a production WSGI server option — with the deliberately unimplemented items enumerated honestly in §17.
Principal engineering finding

The measured value of this project lies less in the pipeline itself — which is an integration of well-understood components — than in the evidence discipline applied to it. A plausible, intuitively-correct preprocessing technique was implemented, measured, found to be actively harmful, root-caused, removed, and regression-tested. The benchmark existed specifically so that such a claim could be falsified rather than assumed.
